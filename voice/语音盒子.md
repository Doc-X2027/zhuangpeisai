# 语音盒子远程终端使用指南

## 1. 用途

本指南用于在 Windows 电脑上通过 SSH 远程登录 BST C1200 语音盒子，启动 ARM 语音服务，并使 Windows 上的 `app.py` 接收语音识别结果。

默认网络参数：

| 项目 | 默认值 |
|---|---|
| 语音盒子 IP | `192.168.34.200` |
| SSH 端口 | `22` |
| 语音服务端口 | `8765` |
| SSH 用户名 | `bst` |
| SSH 默认密码 | `bst2025` |
| 语音服务地址 | `http://192.168.34.200:8765` |

## 2. 连接网线

1. 用网线连接 Windows 电脑与语音盒子所在的局域网。
2. 将 Windows 有线网卡配置为 `192.168.34.X` 网段的空闲地址，例如：

   ```text
   IP 地址：192.168.34.10
   子网掩码：255.255.255.0
   ```

3. Windows 电脑不要使用 `192.168.34.200`，否则会与语音盒子发生 IP 冲突。
4. 如果盒子固定使用有线网卡，按设备部署手册关闭无线网络，避免路由冲突。

## 3. 检查网络

在 Windows PowerShell 中执行：

```powershell
ping 192.168.34.200
Test-NetConnection 192.168.34.200 -Port 22
```

判定方法：

- `ping` 有回复：Windows 与语音盒子网络互通。
- `TcpTestSucceeded : True`：SSH 端口可用。
- `ping` 不通时，先检查网线、Windows 网卡 IP 和语音盒子电源。

## 4. 打开远程终端

在 Windows PowerShell 中输入：

```powershell
ssh bst@192.168.34.200
```

首次连接可能出现主机指纹确认：

```text
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

输入 `yes` 并回车，然后输入设备默认密码：

```text
bst2025
```

输入密码时终端不显示字符，这是 SSH 的正常安全行为。

登录成功后，命令行通常会显示类似：

```text
bst@bst:~$
```

> 如果现场已修改默认密码，以当前设备密码为准。

## 5. 启动语音服务

在 SSH 远程终端中执行：

```bash
cd /home/bst/SpeechRelease
./启动打包语音服务.sh
```

看到以下内容表示服务已启动：

```text
ARM speech real service listening on http://0.0.0.0:8765
```

语音服务在前台运行时，不要关闭该 SSH 窗口，也不要在该窗口按 `Ctrl+C`。

如果出现权限错误，可先执行：

```bash
chmod +x ./启动打包语音服务.sh
./启动打包语音服务.sh
```

### 5.1 一键修改唤醒词

项目已提供 Windows 自动化脚本。它会连接 `192.168.34.200`，备份 `/home/bst/SpeechRelease/SpeechReleaseServer/speech_server.json`，并将其中的 `keyword` 修改为“小聚同学”。Windows 程序使用短句 ASR 对该文本做精确匹配，不使用会接受近音词的盒端自动播报。该脚本不会启动、停止或重启语音服务。

在项目根目录打开 Windows PowerShell，执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start_voice_box.ps1
```

运行过程中出现以下提示时：

```text
bst@192.168.34.200's password:
```

输入：

```text
bst2025
```

脚本使用标准 `ssh` 和 `scp`，因此未配置 SSH 密钥时可能会多次询问密码。密码不会被写入脚本或日志。

修改成功后，PowerShell 会显示 `The speech service was not started`并返回本机终端。如果语音服务在修改时已经运行，需稍后手动重启语音服务，新唤醒词才会生效。

PowerShell 脚本在远程执行前会自动将 Windows CRLF 换行转换为 Linux LF，避免出现 `/usr/bin/env: 'bash\r': No such file or directory`。

## 6. 在 Windows 上检查语音服务

保持 SSH 窗口开启，另外打开一个 Windows PowerShell，执行：

```powershell
Test-NetConnection 192.168.34.200 -Port 8765
Invoke-RestMethod http://192.168.34.200:8765/health
```

正常情况下：

- `TcpTestSucceeded` 为 `True`。
- `/health` 返回 `ready: true`。
- 真实语音服务的 `provider` 为 `real`。

不建议只用浏览器打开服务根地址来判断是否启动成功。根地址显示解析失败不代表后台服务异常，应以 `/health` 结果为准。

## 7. 启动 Windows 主程序

在 Windows PowerShell 中进入本项目目录，然后启动：

```powershell
python app.py
```

`app.py` 默认连接：

```text
http://192.168.34.200:8765
```

`app.py` 不再显示语音地址、“连接”或“识别”选项。程序启动后会在后台自动连接语音盒子，并连续开始带唤醒词的识别轮次。运行日志出现“语音服务已连接”后，可以直接说：

```text
小聚同学
```

机器人播报“我已就绪，请下达指令”后，再说“执行任务一”或“执行任务二”。

| 语音内容 | Windows 程序行为 |
|---|---|
| 短句 ASR 文本精确包含“小聚同学” | 播放“我已就绪，请下达指令”，随后监听任务指令；其他近音词不触发 |
| 语句中包含“执行任务一” | 先调用海康相机拍照，再执行任务 01 图片识别并立即播报 `qwen-vl-plus` 识别结果 |
| 语句中包含“执行任务二” | 先调用海康相机拍照，再执行任务 02 任务卡识别并立即播报 `qwen-vl-plus` 识别结果 |
| 其他语句 | 只显示识别结果，不执行任务 |

当前已有任务正在执行时，新的语音任务指令会被忽略，防止两个任务并发执行。

## 8. 停止服务和退出远程终端

如果语音服务正在 SSH 窗口前台运行，在该窗口按：

```text
Ctrl+C
```

服务停止后，执行以下命令退出 SSH：

```bash
exit
```

直接关闭 SSH 窗口可能会导致前台语音服务一起退出。

## 9. 常见故障排查

### 9.1 `ping` 不通

检查：

- 语音盒子是否已开机。
- 网线和交换机指示灯是否正常。
- Windows 有线网卡是否为 `192.168.34.X/24`。
- Windows 和语音盒子是否误用了相同 IP。
- 盒子的有线网卡 `eth0` 是否仍为 `192.168.34.200`。

### 9.2 SSH 连接被拒绝

执行：

```powershell
Test-NetConnection 192.168.34.200 -Port 22
```

如果端口不通，需在语音盒子本机检查 SSH 服务是否启动、防火墙是否允许 `22/tcp`。

### 9.3 SSH 提示主机指纹发生变化

确认设备确实重装过系统且 IP 没有被其他设备占用后，在 Windows PowerShell 中执行：

```powershell
ssh-keygen -R 192.168.34.200
ssh bst@192.168.34.200
```

不要在未确认设备身份时删除指纹记录。

### 9.4 `8765` 端口不通

检查 SSH 窗口中是否已出现：

```text
ARM speech real service listening on http://0.0.0.0:8765
```

如果没有，重新执行启动脚本并查看报错。还需确认服务绑定的是 `0.0.0.0`，而不是 `127.0.0.1`，并确认防火墙允许 `8765/tcp`。

### 9.5 `/health` 返回 `ready: false`

根据返回的 `error_code` 和 `message` 检查：

- ASR 模型文件是否完整。
- 麦克风阵列驱动是否安装。
- 麦克风、声卡和扬声器是否可用。
- 语音服务依赖是否安装完整。

### 9.6 `app.py` 日志一直显示等待语音服务

1. 先在 PowerShell 中确认 `/health` 可访问。
2. 默认地址为 `http://192.168.34.200:8765`。如果现场地址不同，启动 `app.py` 前通过环境变量 `AUBO_ARM_SPEECH_BASE_URL` 设置。
3. 如果 Windows 设置了 HTTP 代理，确认局域网流量没有被防火墙拦截。当前 Windows 语音客户端已为 ARM 连接禁用系统代理。
4. 语音服务恢复后 `app.py` 会自动重连，无需手动点击按钮。

## 10. 安全边界

- ARM 语音盒子只负责唤醒、录音、VAD、ASR、TTS 和语音事件推送。
- 语音文本到任务的映射由 Windows `app.py` 完成。
- ARM 语音服务不直接控制机器人。
- 真实 ARM 语音链路只有在 `/health`、HTTP ASR 和 WebSocket 事件都经现场验证后，才能记录为联调通过。
